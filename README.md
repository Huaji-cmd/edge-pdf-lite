轻量 **PDF / Markdown 阅读器** + PDF 批注编辑器，面向**低配 Windows**（8 GB 内存那一档）。

> **定位**：不比 Edge 差，但**只在必须付的时候付一次**；并且做 Edge 没有的几件事
> —— 双页并排、阅读位置记忆、批注写回 PDF，以及把 Markdown 笔记并进同一个阅读器
> （只读、可缩放、有标题大纲；要批注就先转 PDF）。

> 📌 **`v2.0.0`**：从"PDF 批注编辑器"长成 **PDF / Markdown 双格式阅读器** ——
> Markdown 只读阅读（大纲 / 字号缩放 / 公式 / 代码高亮 / 本地图片）、双端 Ctrl+F 页内查找、
> 应用内一键转 PDF（Edge 无头打印，零安装依赖）。
> 上一版 `v1.4.0` 收的两条硬伤（划线串行、大文件保存几分钟）完整说明在下面的更新日志里。

> 仍为**个人项目**：不接收 PR（理由见 [SECURITY.md](SECURITY.md)），Issue 可以提。

![阅读界面](docs/images/reader.png)

- **网页版**：浏览器里直接打开就能用。
- **桌面版**（Tauri v2）：能拿到文件真实路径，所以文件列表能记住、能覆盖原文件。

## 更新日志

### `v2.0.0` — 多格式阅读：PDF + Markdown（2026-11-06）

| 变化 | 说明 |
|---|---|
| **能读 Markdown 了** | `.md` / `.markdown` 与 PDF 混在同一个文件列表里，拖放 / 对话框 / 文件夹扫描都认 |
| **只读 + 字号缩放** | 连续滚动，缩放改的是字号并自动重排（75%–250%），**不会**让整页出现横向滚动条 |
| **标题大纲** | 用 `#` 标题生成目录，点击跳转、滚动时高亮当前小节 |
| **位置记忆** | 记住缩放 + 滚动位置 + 最近标题，换一篇再换回来能回到原处 |
| **本地图片** | 桌面端读同目录 / 子目录（`../` 越界被 Rust 拒绝）；**Typora 的绝对路径图片**：打开时弹窗列出完整路径清单，允许后显示（授权只登记那些文件、仅本次运行有效）；浏览器版点占位授权文件夹后显示（File System Access）；远程图片不联网 |
| **安全基线** | 原始 HTML 一律转义、再经 DOMPurify；链接只允许 http / https / mailto；外链交给系统浏览器 |
| **应用内转 PDF** | 桌面版工具栏「转 PDF 后批注」**一键转换**：选保存位置 → 生成 PDF → 自动打开批注。渲染用的是应用自己的管线（预览看到什么 PDF 就是什么，公式/代码高亮/本地图片都在），打印引擎是系统自带的 Edge 无头模式 —— **零安装依赖**。浏览器版仍给出外部工具引导 |
| **数学公式** | `$...$` 行内 / `$$...$$` 块级，KaTeX **按需加载**（没有公式的文档一个字节不多付）。定界规则是**自己写的**（不用 texmath）—— 行内代码里的 `$VAR`、货币 `$5`、转义 `\$` 都不会误判成公式 |
| **代码高亮 + 文件徽标** | 代码块按语言着色（颜色全部映射主题变量，日间/夜间都对）；highlight.js 是**动态加载**的 —— 没有代码块的文档一个字节都不多付。文件列表和搜索结果里，通用文件图标被 **PDF / MD 徽标**替代（文件名反而更宽） |
| **页内查找（Ctrl+F）** | Markdown 和 PDF **都支持**（共用同一个查找条）：全部匹配浅黄底、当前项橙色，Enter / Shift+Enter 逐个跳，Esc 关闭。Markdown 用 CSS Custom Highlight API（不往正文插标记，缩放重排不乱）；PDF 全文档搜索、跨页跳转（页码与视口自洽）、缩放后高亮自动重打 |

PDF 的批注、写回、单双页、缩略图、保存全部保持原行为（回归测试覆盖）。

### `v1.4.0` — 划选手感 + 大文件保存（2026-11-05）

| 问题 | 处理 |
|---|---|
| **划线时会串到别的行**（想选第 1~2 行，鼠标划过两行之间的空隙，结果下面三行全被选中） | 根因不是鼠标落点，是**文本层的 DOM 顺序不等于视觉顺序**。pdf.js 按 PDF 内容流生成 span，实测某一页的顺序是 `[标题, 说明行, 页脚NM, 页脚author, Line1, Line2, Line3, Line4]` —— 正文排在页脚之后。而浏览器的 Range 只能按 DOM 顺序，于是从 Line2 拖到 Line3，夹在中间的页脚被一起圈进去。现在文本层挂上之后会按视觉位置重排（绝对定位元素，重排不影响任何视觉表现），选区就是连续的了 |
| **几十 MB 的书保存要等好几分钟**（实测 92 MB / 376 页的扫描书、18 条批注，3 分钟没反应） | 瓶颈不在 pdf-lib（它对这本书只要 128 ms），而在**把整份 PDF 编成 base64 走 IPC**：92 MB → 123 MB 字符串，光浏览器里的字符串拼接就 1.8 s，后面还有 JSON 序列化、跨进程传输、Rust 侧反序列化 + base64 解码，中间几百 MB 的堆峰值。现在增量更新的产物**只传那一小段尾巴**（几 KB），由 Rust 复制原文件再追加 → 同一本书 **3 分钟 → 0.26 秒** |
| 批注条数越多保存越慢 | 每条批注构造时会触发一次全库扫描（`context.obj()` 逐字段 `set` → 找不到对象号 → 全表深搜）。改成"屏蔽期造对象"后，600 页文字版 28 条：6.3 s → 1.3 s |
| 保存后徽标不归零 / 数字对不上（"保存后 8 条，再做 3 条还是 8 条"） | 徽标原本有几处推的是**总条数**而不是**未保存条数**，一打字/删批注就跳回总数。现在统一走同一个入口 |
| 刷新文件夹时提示"扫了 N 个文件夹" | 去掉。扫了几个是实现细节，对你没有意义；没有新增文件时干脆不提示 |

**为什么以前没发现**：测试一直用 2 MB 的样本 —— `base64 + IPC` 在 2 MB 上只要几十毫秒，
"DOM 顺序乱"在单栏短文档里也看不出来。这两个坑都是"92 MB 的书 + 双栏/多段排版"才暴露的。

`write_pdf_tail` 的前置条件写得很死：必须**有真实文件路径**、产物**以原文件字节为前缀**
（即真的是增量）、且**原文件长度和读进来时一致**（读完之后被人改过就拒绝写，宁可让你重开）。
任何一条不成立就走回老路（整份 base64），浏览器版和拖进来的文件都走老路。


### `v1.3.0` — 中文文本框 + 保存链路修复（2026-10-27）

| 问题 | 处理 |
|---|---|
| **中文文本框保存后全变成灰条**（只有纯英文正常） | 根因是标准 14 字体**没有 CJK 字形**，旧实现干脆画"占位横线"。现在改成**运行时读系统字体**（`%WINDIR%\Fonts\simhei.ttf`）→ fontkit **子集化嵌入**：一份三行中文的 PDF 只多 ~5 KB（全量嵌入才是 9.7 MB）。字体不进安装包，lite 的定位没变。浏览器版读不到系统字体，仍退占位横线并明确提示 |
| 收起批注面板后**还能继续画** | 收起 = 退出批注模式（工具清成 `none`）。以前"收起"只是把按钮藏起来，工具还亮着 |
| 保存之后**批注条数不归零** | 徽标语义改成"**还没写回文件的条数**"（新增 / 改过 / 删掉都算），保存即归零，但批注本身**留在屏幕上**（不是靠删内容来归零） |
| 桌面端点 ✕ **不提醒未保存** | 关窗口走的是 Tauri 的 `CloseRequested`，不保证跑 `beforeunload`。现在显式拦截，确认后才销毁窗口。⚠️ 确认框用 Tauri 原生 dialog：`window.confirm` 在 WebView2 里会把页面 JS 整段阻塞，表现是"点 ✕ 像死机" |
| **只读 PDF 覆盖保存必失败** | 网盘 / 压缩包解出来的 PDF 常带 `FILE_ATTRIBUTE_READONLY`，`fs::write` 直接"拒绝访问"。现在写前**取消只读**（备份已经先做过），提示里会说明 |
| 保存失败只显示 **`undefined`** | Tauri 命令失败时 reject 的是**字符串**，`(e as Error).message` 取不到内容 —— 真正的错误被吞掉了。现在统一走 `errTextOf()`，原样显示 |
| 另存路径显示成 `\\?\D:\tmp\…` | 那是 Rust `canonicalize()` 的规范化形式，以前被直接返回给前端。现在**显示 / 存设置 / 交给 explorer 一律用干净路径**，白名单内部仍存规范形式；老数据加载时自动洗净 |
| `.bak` 固定落在原文件旁边 | 设置里可选：**跟原文件同目录**（默认）/ **跟保存位置一致**。提示里给出备份的**完整路径**（由 Rust 回传，不是前端猜的 `.bak` / `.bak2` 编号） |
| 设置图标看着像"日间模式" | 原来的 `gear` 画成了"圆心 + 一圈放射线"，跟太阳图标撞脸；换成带齿的齿轮轮廓 |

字体这块的验证方式：把 exe 保存出的 PDF 用 **pdfium（Edge 同引擎）** 渲染成图看中文，
再用 pdf-lib 查结构（`/AP` 里必须是 **Type0 + FontDescriptor/FontFile2**）——
退回占位线时这两项为 0，所以它不是假绿。

### `v1.2.0` — 批注交互修复（2026-10-19）

全是长期使用后暴露的问题，逐条都有回归用例：

| 问题 | 处理 |
|---|---|
| 高亮 / 下划线 / 删除线选中后还能拖动缩放 | 锁定为**只可选中、只能删** —— 位置由原文决定，拖一下会盖到别的句子上，肉眼很难发现 |
| 手写笔迹选中后能缩放 | 同上，一并锁定（8 个角点手柄彻底移除） |
| 区域高亮 / 方框的手柄不好用 | 改成和文本框一致的**「左边移动条 + 上/右/下三边拉伸」** |
| 触屏下文本框移动、拉伸都用不了 | 手柄声明 `touch-action: none`（`preventDefault()` 挡不住，手势开始前就得声明）；热区放大到 38×44，且视觉圆圈回到框边界上 |
| 新加文件夹 / 另存文件后列表不刷新 | 新增刷新按钮，重扫已展开目录并**复用旧节点**（不把展开层级弄塌） |
| 从大纲切回文件列表，文件夹要重新展开 | 展开状态持久化，键用**真实路径**而不是会话内自增 id |
| 打开缩略图总是从第 1 页开始 | 挂载后定位到当前页 |
| 删掉页面上**最后一条**批注，字还留在画布上 | 异步重绘抓的是删除**之前**的快照，`await` 之后才落笔把旧数据画回去；现在空列表分支也作废在途请求，且**落笔前重新取一次数据** |
| 下划线偶尔变成**两条平行线** | `getClientRects()` 把一行拆成多个高度不同的矩形；现在先按垂直重叠聚成一行，组内上下边取并集 |

## 为什么做这个

低配 Windows 上打开一份几十 MB、每页是一整张大图的 PDF，Edge 也会卡。但"卡"的
原因不是内核差，而是**首次打开一页要解码一整张图**——这是硬成本，谁都省不掉。

所以这个项目的目标不是"比 Edge 快"，而是：

1. **不重复付费** —— 翻回去看过的页立刻出来，滚动保持满帧；
2. **补齐 Edge 缺的** —— 双页并排、按内容指纹记住阅读位置、批注写回 PDF；
3. **严守 scope** —— 不做 OCR、不做页面操作（删页 / 合并）、不改 PDF 原有文字。

## 功能特性

| | 说明 |
|---|---|
| **阅读** | 单页 / 双页并排、按行翻页、缩略图、PDF 书签跳转、**Ctrl+F 页内查找**（全文档、大小写不敏感、跨页跳转，高亮画在文本层里像素级准） |

| **打开记忆** | 桌面端还会记住**上次看的是哪一篇**，重开应用自动打开它（路径失效就退回欢迎页并提示） |

| **批注** | 高亮（不盖住文字）、下划线、删除线、区域高亮、手写（三档笔尖粗细）、方框、文本框 |
| **文本框** | 点页面**就地**出现编辑框（左实心条拖动、右圆圈调宽）、到框宽自动换行、字号三档 + 字体颜色；点空白处收起，文字与 PDF 融为一体。**中文会嵌入字体子集**，在 Edge / Acrobat 里也是真字 |
| **编辑** | 选中后可拖动 / 改大小 / 改颜色 / 删除，撤销 · 重做 |

| **触屏** | 单指画 / 划选文字，双指平移 · 缩放（Surface 上验证过） |
| **文件列表** | 桌面端：真实路径、跨会话记住、点开文件夹才扫一层（懒加载）、右键可重命名 / 在资源管理器打开 / 复制路径 |

| **外观** | 日间 / 夜间 / 跟随系统 |

## 快速开始

### 直接用

下载 [Release](https://github.com/Huaji-cmd/edge-pdf-lite/releases) 里的
`edge-pdf-lite.exe`（免安装，双击即用），或安装 NSIS / MSI 安装包。

要求：Windows 10+（自带 WebView2 运行时）。

### 从源码

```bash
npm install          # postinstall 会自动拷 pdf.js 的 cmaps / 标准字体
npm run dev          # http://localhost:5173
```

想跑测试的话，先把样本备齐：

```bash
npm run testdata         # = testdata:local + 取回真实论文语料（一条命令搞定）
npm run testdata:local   # 只生成合成样本，不联网
npm run testdata:real    # 只取回真实论文语料（arXiv，约 2.2 MB）
```

`public/testdata/` 整体**不入库**：

- 合成样本（文字页 / 矢量页 / 对照实验样本）由脚本当场生成；
- 「真实论文语料」按需取回 —— 它是 arXiv 电子预印本，**没有再分发的授权**，
  放进仓库等于替别人分发。测试用它是有理由的：合成样本验证不了真实文档的页面构成
  （内嵌字体 + 整页图片 + 上百条既有注释），好几个决定性结论都只能在它上面测出来。

拿不到 arxiv.org 的时候（公司 / 校园网常见）：

```bash
EPL_REAL_PDF_URL=<镜像地址> npm run testdata:real
```

或者**直接把你手边任意一份真实 PDF 改名放过去** —— 测试不检查它的内容，
只要"有文字层、有图片"就够：

```
public/testdata/real-1706.03762.pdf
```

## 它是怎么守住"轻量"的

这些结论**都是实测出来的，不是推理的**（方法和数据见 `docs/M0-裁剪渲染实验结论.md`）：

| 结论 | 数据 |
|---|---|
| 滚动 | ✅ 满帧 60 fps —— **滚动本身不卡** |
| 真正的痛点 | 新页出现慢（白屏 185–409 ms），不是掉帧 |
| 首次打开一页 | 图片版 ≈334 ms；文字版 ≈99 ms |
| 重复渲染 | ✅ pdf.js 自带缓存：171 ms → 13.6 ms |
| 裁剪渲染 | ⛔ **已证伪**（图片页 0.86–0.94×）—— 解码是整张的，裁剪省不掉 |
| 加载选项 | ⛔ `enableHWA` / `useSystemFonts` / `disableFontFace` 全部 ≈1.00× |

🔴 **决定性对照**：同一本书在 Edge（C++ PDFium）里打开**同样卡** ——
所以那不是内核差距，是这台机器处理"每页一整张 4.5 MP 图片"的上限。

**能承诺**：不重复付费、滚动不卡、缩放不逐帧重渲染、Edge 没有的功能。
**不能承诺**：首次打开一页比 Edge 快（解码是硬成本）。

刻意**不做**：OCR、页面操作（删页 / 合并）、修改 PDF 原有文字 —— 这些一做就不 lite 了。

## 已知限制

诚实清单 —— 开源项目的信誉靠这个，藏起来只会让人踩坑后更失望。

| 限制 | 说明 |
|---|---|
| **已有的批注擦不掉** | 打开 PDF 时，文件里原有的注释**不进**编辑列表 —— 看得见，但不能擦、不能拖 |
| **中文文本框：网页版只能画占位线** | 桌面版会**嵌入系统中文字体（子集化，一份 PDF 只多几 KB）**，在 Edge / Acrobat 里正常显示中文。浏览器版读不到系统字体，退回**占位横线**（文字仍完整存在 `/Contents` 里，应用内和注释面板都能看全），保存时会明确提示 |
| **写回在主线程** | 加批注/序列化都在主线程（92 MB 的书上是 100 ms 级，暂时不值得搬 Worker）；真正花时间的那段（IPC + base64）已经不走了 |
| **大文件增量写入未测** | 小文件上增量既不快也不小；它的价值在大文件（峰值内存），但大文件还没实测 |
| **无边框窗口** | 换来了自绘标题栏，代价是失去系统"拖到边缘自动分屏" |
| **网页版没有真实路径** | 浏览器拿不到文件路径，所以文件列表不能跨会话记住、不能覆盖原文件、**也不会自动打开上次那篇**（界面上会明确说明） |
| **会改文件属性** | 覆盖保存到**只读**文件时，会先取消它的只读属性（否则写不进去）——提示里会明说，`.bak` 已经先留好了 |
| **位置记忆** | 按内容指纹存，同一份文件改名 / 移动都认；但文件被大改后指纹变化会丢失记忆 |
| **Markdown 不能批注** | 这是刻意的产品边界：只读、不写回、不支持划词高亮。要批注请先用外部工具（Typora / VS Code 扩展 / Pandoc）转成 PDF，再把 PDF 拖回来 |
| **Markdown 没有页的概念** | 不显示页码、单双页、缩略图；也不做数学公式、Mermaid（都列在后续） |
| **公式定界的已知边界** | 行内公式不跨行；同一行里"未配对 `$` + 行内代码反引号"混排时，配对可能越界（保守拒绝更可预测）；`\(...\)` 定界符不支持（只认 `$`） |
| **代码块不标语言就不高亮** | 高亮只认标了语言（如 ```` ```ts ```` 围栏）的块 —— 自动猜语言是纯 CPU 消耗，长代码在低配机上能卡出感知，还常猜错。没标的保持等宽纯文本 |
| **页内查找找不到"跨样式"的词** | 查找按 DOM 文本节点匹配：`**粗**体`、`行内代码` 这类被拆成多段的词搜不到（单字/短语不受影响） |
| **Markdown 文件上限 16 MiB** | 这类文件要一次性解析完并建 DOM，再大在低配机上会卡界面；超限会明确提示而不是静默失败 |
| **远程图片不加载** | Markdown 里的 `http(s)` 图片只显示占位（不联网、不追踪） |
| **笔记外图片每次运行要授权一次** | 绝对路径图（Typora 场景）打开时会列出完整路径请你确认；授权只登记列出的**文件**（不放开目录）、重启即清空。想免确认就把图片挪进笔记文件夹用相对路径 |
| **浏览器版本地图片要授权一次** | 浏览器拿不到同目录的兄弟文件，需要点占位**授权笔记所在文件夹**（每会话一次；不支持 File System Access 的浏览器才显示"仅桌面版"）。授权只读那一个文件夹，`..` 在 API 层面进不去 |

## 常见问题：启动出来一个"乱码错误页"

这是一个**不用重装**的问题，而且现在已经能自愈。

**现象**：双击打开，窗口里只有一行乱码（其实是 WebView2 自己画的错误页，UTF-8 中文被按 GBK 显示，
内容是「找不到 tauri.localhost 的服务器 DNS 地址」）。这不是我们界面白屏，是 WebView2 的
**虚拟主机映射**失效了 —— Tauri 把前端资源挂在 `http://tauri.localhost` 上，映射一坏，
请求就跑到真实网络去解析这个域名。

**怎么办**（按推荐顺序）：

1. **什么都不用做，直接再打开一次** —— 应用会自己发现"上次没启动成功"，把 WebView2 的
   profile 清掉重建（`%LOCALAPPDATA%\com.edge-pdf-lite.desktop\EBWebView`）。
   **你的文件列表和设置不会被清掉**（它们单独放在 `Default\Local Storage` 里）。
2. 想手动来一遍也行：把上面那个 `EBWebView` 目录整个删掉再启动。代价是文件列表 / 设置在
   `Local Storage` 里会一起没 —— 所以只在第 1 条不管用时再用。

**已经做了哪些防范**：

- **单实例保护**：第二次双击不会再开一个 WebView2 会话（两个实例抢同一个 profile 会把
  它搞坏），而是把已有窗口拉到前面。
- **启动失败的自我判定**：`setup` 里先记一笔「这次启动还没证明自己是好的」，前端跑起来后
  再用更新的一笔盖过去。所以**白屏一次，下一次启动就会自愈**。
- 自愈**只在启动前、且进程里还没有 WebView2 的时候做**（那时删文件才删得干净），
  并且会先确认没有别的实例正在用这个 profile。

## 下载与校验（防投毒）

exe **没有做代码签名**（签名证书要花钱，这是个人项目），所以 Windows 会弹
「Windows 已保护你的电脑 / 未知发布者」—— 点「更多信息」→「仍要运行」即可。
介意的话可以自己从源码编译。

正因为没有签名，**校验只能靠自己动手**，两步：

1. **只从本仓库的 [Releases](https://github.com/Huaji-cmd/edge-pdf-lite/releases) 页下载。**
   任何第三方站点的同名 exe 都不能当作本项目产物 —— 每个 Release 的资产自上传后就不再
   改动，所以这里永远是唯一的权威来源。
2. **下完核对 SHA256**：每个 Release 的说明里都给了三个资产的校验和，
   本地算出来比对即可：

   ```powershell
   certutil -hashfile edge-pdf-lite.exe SHA256
   ```

   或者 Git Bash 里：

   ```bash
   sha256sum edge-pdf-lite.exe
   ```

对不上就不要运行，直接删掉。

## 技术栈

| 层 | 选型 |
|---|---|
| 渲染 | **pdf.js 6.x**（现代构建 + 自带 ES2025 polyfill，见 `docs/在另一台机器上测试.md`） |
| 界面 | **Vue 3** `<script setup>` + TypeScript + Pinia |

| 桌面外壳 | **Tauri v2**（Rust，WebView2） |

| Markdown 转 PDF | 自包含打印 HTML（公式/高亮静态化、KaTeX 字体 base64 内嵌）+ **系统 Edge 无头打印**（`--print-to-pdf`，独立 user-data-dir）—— 不引入 Pandoc 及其数百 MB 的 PDF 引擎 |
| Markdown | **markdown-it**（`html:false`，只开 GFM 基础语法）+ **DOMPurify**（产物再净化一遍）+ 自己写的链接/图片重写 |

| 测试 | 零框架：Node 22 内置 WebSocket + **CDP** 驱动真实浏览器 / WebView2 |

## 验证方式

端到端测试全部用 **CDP**（headless Edge / WebView2 的调试端口），零测试框架依赖：

- **发真实事件**（`Input.dispatchMouseEvent` / `dispatchTouchEvent`），不是直接调函数 ——
  这样能顺带验证指针捕获这类只有真实交互才暴露的问题。
- **判据要求"有牙"**：每条断言都要能抓住对应的失败。
  比如判"批注写进去了"用的是 pdf-lib 直查 `/Annots` 且要求**恰好 +1**
  （测试样本本来就带 113 条批注，写成"大于 0"的话 writer 一行不写也照样绿）。
- 新判据一律做**变异测试**：把修复注回去，确认测试真的变红，再还原。
- `npm test` **十套**（含 Markdown 通道与 PDF 查找）；`npm run test:exe` **133** 项（含打包后桌面端专有能力）；
  `npm run test:exe:heal` 另测 profile 自愈与单实例。
- Rust 侧另有 **10 项单元测试**（`cd src-tauri && cargo test`），只测纯逻辑：
  图片相对路径的越界拒绝、扩展名白名单、PDF / Markdown 的大小闸门、
  Edge 打印冒烟（真转换一份 HTML 验 PDF 魔数）。
  这条是专门为 `read_doc_asset` 加的 —— 端到端只能证明"读不到"，
  分不清是**被规则拒绝**还是**文件刚好不存在**。
- `npm run test:exe:big` 拿一本真实的大 PDF（自备到 `my-test-books/`）走完整 UI 保存一次，
  断言**耗时上限**和"产物 = 原文件 + 几 KB、批注数 + N、页数不变"。
  这个脚本是专门为 `v1.3.1` 那个"92 MB 保存 3 分钟"的坑加的 —— 小样本永远测不出来。

## 安全

- **CSP 锁到 `'self'`**（`src-tauri/tauri.conf.json`）：没有 `'unsafe-inline'`、
  没有 `unsafe-eval`，`object-src` / `base-uri` / `form-action` / `frame-ancestors` 全为 `'none'`。
  这是**实测可用**的策略，不是照抄模板 —— 完整推导见 `docs/M13-打包成exe.md` 第七节。
- CSP 设错的症状**不是报错**，是"某个功能悄悄没了"（worker 被拦 → pdf.js 静默退回主线程，
  页面照常显示只是卡）。所以有独立的 `npm run test:csp`：**主动监听 `securitypolicyviolation`**，
  并断言"0 违规"同时"内容真的画上去了"，避免白屏时的假绿。
- 前端不引入任何第三方 CDN 资源，全部走本地打包。
- **文件读写只放行你亲手选过的路径**：读 / 写 / 列目录 / 重命名这几个命令都会先把路径
  `canonicalize()` 再比对白名单，范围外一律拒绝。登记只发生在 Rust 侧（前端没有"加白名单"
  的接口）—— 即使某天前端被注入脚本，它也读不到、写不进你选过的范围之外。
- **隐私清理（公开前做过一轮，你可以自己复核）**：
  - 提交作者 / 提交者邮箱统一是 `Huaji-cmd@users.noreply.github.com`（GitHub 的匿名转发地址，
    不暴露真实邮箱）；
  - 全历史（含**已删除的文件**和 **commit message**，不只当前工作区）扫过本机路径、
    邮箱、手机号、身份证、内网 IP、各类平台 token 与私钥格式 —— **真实命中 0 条**；
    文档里那些 `C:\Users\你\...` 是占位符，不是真值；
  - 复核命令（在本仓库里跑）：

    ```bash
    git log --all --format='%an <%ae>' | sort -u          # 提交身份
    git log --all --format='%cn <%ce>' | sort -u          # 提交者身份
    git log --all -p | grep -aiE 'users\\|ghp_|BEGIN [A-Z ]*PRIVATE KEY'
    ```

- 安全问题的报告方式、以及**为什么本仓库不接收代码补丁**，见 [SECURITY.md](SECURITY.md)。
  仓库不再归档、Issue 可用；但代码补丁仍然不收 —— 想改请 fork。
