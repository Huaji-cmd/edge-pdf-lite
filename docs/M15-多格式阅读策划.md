# edge-pdf-lite · 多格式阅读器策划稿（PDF + Markdown）

> 状态：**已实现**（2026-11-05，见文末「实施记录」）；本文件保留为决策依据。
> 结论：可行，基础版改动量中等；推荐新增独立的 Markdown 阅读通道，不改造现有 PDF 渲染与批注核心。
> 目标版本：v1.5（暂定）。产品名保留 `edge-pdf-lite`，仅调整文案。
> 文档位置：`docs/M15-多格式阅读策划.md`（2026-11-05）。

---

## 1. 结论摘要

| 项目 | 结论 |
|---|---|
| 可行性 | **可行**。应用外壳、文件列表、主题、设置、侧边栏、窗口控制可复用 |
| 基础版难度 | **中等**，约 **7–10 人日**（含测试与安全加固） |
| PDF 风险 | **中高**，但不能为零。采用“PDF 路径不动 + Markdown 独立通道”控制回归 |
| 最大风险 | Markdown 的 HTML / 本地图片 / 外链安全边界，其次是 PDF 既有链路被条件分支污染 |
| 最大工作量 | 不在 Markdown 渲染，而在文件入口统一、UI 能力矩阵、阅读状态、测试回归 |
| 内置转 PDF | **本期不做**。v1 只做外部转换引导，避免引入排版引擎或 WebView2 打印链路 |
| 推荐策略 | 先交付“能读、能缩放、能定位”的只读 Markdown，再补导航与体验 |

**一句话方案**：把“文档”从 PDF 单一类型扩展为 `pdf | markdown` 两类；PDF 继续走现有 `PdfDocument + PdfViewer`，Markdown 新增 `MarkdownDocument + MarkdownViewer`；App 只做类型分流和外壳适配。

## 2. 目标与非目标

### 2.1 本期目标

1. 支持通过文件选择、拖放、文件列表、上次阅读恢复打开 `.pdf` / `.md` / `.markdown`。
2. Markdown 只读渲染，支持 GFM 基础语法：表格、任务列表、删除线、自动链接。
3. Markdown 仅支持缩放；缩放采用**字号缩放并自动重排**。
4. Markdown 不显示页码、单双页、缩略图、PDF 书签、批注、保存批注等 PDF 专属能力。
5. Markdown 支持标题大纲，可点击跳转并高亮当前标题。
6. 按内容记忆 Markdown 的缩放比例与阅读位置。
7. 桌面端支持同目录及子目录内的本地图片；远程图片不自动加载。
8. Markdown 工具栏提供“转 PDF 后批注”引导，说明由外部工具完成转换。
9. 保持 PDF 现有功能、保存链路与路径白名单不回退。

### 2.2 明确不做

- Markdown 编辑、保存、批注、划词高亮。
- Markdown 单双页、分页、缩略图、页码。
- 应用内 Markdown → PDF 转换（本期）。
- Markdown 全文检索、跨文档索引。
- 数学公式、Mermaid、代码语法高亮（本期不做，列为后续）。
- 远程图片自动加载。
- 账号、同步、云存储。

## 5. 总体方案

### 5.1 文档类型与分流

```text
文件选择 / 拖放 / 文件列表 / 上次文档
                │
                ▼
        readDocBytes / File
                │
       按扩展名判定 kind
        ┌───────┴────────┐
        ▼                ▼
  PdfDocument       MarkdownDocument
        │                │
   PdfViewer        MarkdownViewer
        │                │
   PDF 工具栏         Markdown 工具栏
```

建议不要引入“万能 Document 接口”强行统一两套阅读器。v1 采用**并列会话状态**：

- 保留 `doc: PdfDocument | null`，PDF 代码路径不动。
- 新增 `mdDoc: MarkdownDocument | null`。
- 新增 `docKind: 'pdf' | 'markdown' | null` 作为 UI 分流依据。
- `openBytes()` 只增加 Markdown 分支；PDF 分支保持原逻辑。
- `viewerRef` 与 `mdViewerRef` 分开，避免类型断言扩散。
- 切文档前必须先 `flushSave()` 保存当前 PDF 位置，再替换会话并关闭旧 `PdfDocument`；Markdown 位置写自己的键，**禁止复用 PDF 的 `flushSave`**。
- `watch([page, scale, mode, spreadOffset])` 保留给 PDF；Markdown 的缩放/滚动用独立 watch，避免把文本缩放写成 PDF 阅读记录。

这是典型的“绞杀式”扩展：新能力独立生长，旧链路不被重写。

### 5.2 新增核心文件

| 文件 | 职责 |
|---|---|
| `src/viewer/documentKind.ts` | 扩展名识别、支持类型判断、显示标签 |
| `src/viewer/markdownDocument.ts` | 字节解码、内容指纹、标题提取、渲染数据准备、资源释放 |
| `src/viewer/MarkdownViewer.vue` | 只读渲染、字号缩放、滚动、大纲联动、图片/链接处理 |
| `src/viewer/mdReadingState.ts` | Markdown 专用阅读位置记忆 |
| `src/viewer/MarkdownOutlinePanel.vue` | 标题大纲（或复用通用列表样式） |
| `src/viewer/ConvertGuideDialog.vue` | 外部转 PDF 说明、复制路径、打开文件夹 |
| `src/viewer/markdown.css` 或组件内样式 | 正文排版、代码块、表格、引用、深浅主题 |

### 5.3 关键用户流程

**A. 正常阅读 Markdown**

打开文件 → 识别为 Markdown → 显示标题与正文 → 工具栏只保留缩放与“转 PDF 后批注” → 滚轮滚动 / Ctrl+滚轮缩放 → 大纲跳转 → 关闭后重开恢复位置。

**B. 从 PDF 切到 Markdown**

若当前 PDF 有未保存批注 → 先弹出原有确认 → 确认后保存 PDF 阅读位置 → 关闭 PDF 会话 → 打开 Markdown → 不显示任何批注入口。

**C. 用户想在 Markdown 上批注**

看不到批注工具 → 点“转 PDF 后批注” → 弹窗说明用外部工具转换 → 复制路径 / 打开文件夹 → 用户转换后把 PDF 拖回应用，按原有 PDF 批注流程处理。

**D. 打开含本地图片的 Markdown（桌面端）**

解析相对路径 → 拒绝绝对路径/越界路径 → Rust 在文档目录内读取图片 → Blob URL 渲染 → 文档关闭时统一回收。

## 6. 模块划分与改动点

### M1. 文件入口与类型闸门（难度：S–M）

| 位置 | 改动 |
|---|---|
| `src/viewer/documentKind.ts`（新增） | `pdf / md / markdown` 判定；统一 `isSupportedDocument(name)` |
| `src/viewer/fileList.ts` | `isPdf` → `isSupportedDocument`；添加文件/文件夹、浏览器目录都接受两类；读字节函数改名或新增 `readDocBytes` |
| `src/App.vue` | 拖放白名单、`accept`、打开逻辑、最近文档恢复按类型分流；文案从“PDF”改为“文档” |
| `src/viewer/FilesPanel.vue` | 两个 `<input>` 的 accept 扩展；空状态文案 |
| `src/viewer/SearchPanel.vue` | 无需逻辑改动，文案可泛化 |
| `src-tauri/src/lib.rs` | 新增/改名 `pick_documents`；`list_dir` 接受 md/markdown；新增 `read_doc_bytes`；**写 PDF 的 `ensure_pdf_ext` 保留** |

关键约束：

- 路径白名单机制不变，仍然只放行用户亲手选过的路径。
- 读取闸门按扩展名放行 `pdf/md/markdown`；写入闸门仍只允许 `pdf`。
- 文件大小：PDF 维持 2 GiB 上限；Markdown 设 **16 MiB** 上限，避免单文件解析拖死低配机，超限要给明确提示。
- 类型判断以**扩展名**为准，不依赖 MIME：`.md` 在不同系统常被报成 `text/plain`。
- Markdown 大小上限在 Rust 读取前 `stat` 拦截，前端再做一次兜底。

### M2. Markdown 文档模型（难度：M）

`MarkdownDocument` 负责：

1. 字节 → 文本：UTF-8 优先，识别 BOM，非法字节替换而非抛错。
2. 内容指纹：优先 SHA-256；不可用时回退“名称 + 长度 + 轻量哈希”。
3. 标题提取：解析 AST 或 token，生成稳定 `id`；重复标题追加序号，支持中文标题。
4. 渲染：`markdown-it`（`html: false`、`linkify: true`）→ 安全过滤 → HTML。
5. 生命周期：释放图片 Blob URL、清空缓存。

**安全基线**：

- 原始 HTML **转义，不执行**。
- 输出再经 DOMPurify 白名单过滤，禁止 `script / iframe / object / form / style / on*`。
- 链接只允许 `http / https / mailto / #anchor`；`javascript:`、`data:`、本地相对文件链接一律拒绝。
- 所有外链加 `rel="noopener noreferrer"`，且点击被拦截后交给系统浏览器，不在 WebView 内导航。

### M3. Markdown 阅读器与排版（难度：M–L）

`MarkdownViewer.vue`：

- 连续滚动，无分页。
- 正文最大宽度约 760–820px，居中；窗口变窄时自适应。
- 基础字号 16px 为 100%，行高约 1.75；中文字体走系统字体栈。
- 缩放范围建议 **75%–250%**，默认 100%。
- 缩放通过 CSS 变量改根字号，正文自动换行；图片 `max-width: 100%`；表格、代码块自身横向滚动，不让整页横滚。
- 支持 `Ctrl + 滚轮`、`Ctrl + + / - / 0`。
- 选中与复制可用，但不可编辑。
- 滚动位置节流上报给 App，用于位置记忆和大纲高亮。

排版覆盖：

- 标题、段落、列表、任务列表、引用、代码块、行内代码、表格、分割线、图片、链接。
- 代码块不做语法高亮；等宽字体 + 横向滚动。
- 深色 / 浅色主题使用现有 CSS 变量。
- 图片加载失败或远程图片：显示占位与替代文本，不自动联网。

### M4. 本地图片与外部链接（难度：M，安全敏感）

**本地图片（仅桌面端 v1）**

- 以 Markdown 文件所在目录为根，只允许解析同目录及子目录。
- 解析 `src` 时先 `decodeURIComponent`、统一 `/` 与 `\`，然后**拒绝绝对路径、盘符路径、UNC 路径**，只接受相对路径。
- 新增 Rust 命令 `read_doc_asset(docPath, relPath)`：
  1. `allowed.check(docPath)`；
  2. 校验 docPath 为 md/markdown；
  3. 目标路径 canonicalize；
  4. 必须 `starts_with(doc_dir)`，阻断 `../` 越界；
  5. 只允许常见位图扩展名（png/jpg/jpeg/gif/webp/bmp；SVG 建议 v1 不支持）；
  6. 单图大小上限（建议 20 MiB）；
  7. 以 `tauri::ipc::Response` 返回原始字节。
- 前端转为 Blob URL 显示；文档关闭时统一 `revokeObjectURL`。
- 浏览器版无法读取同目录兄弟文件，显示占位并说明“桌面版可显示本地图片”。

**外部链接**

- 容器级点击拦截，阻止默认导航。
- `#heading` 在文内滚动。
- `http/https/mailto` 走受控命令或 opener 插件打开系统默认程序。
- 相对路径、`file:`、`javascript:` 等给出“暂不支持”提示，不尝试打开。

### M5. 工具栏与界面能力矩阵（难度：M）

**Markdown 工具栏**

保留：

- 打开文件
- 缩小 / 当前百分比（点击回 100%）/ 放大
- “转 PDF 后批注”入口

隐藏：

- 页码、上一页/下一页
- 适应宽度、适应整页
- 单页/双页/封面偏移
- 指针模式、全部批注工具、撤销/重做、未保存标记、保存批注

**能力矩阵**

| 能力 | PDF | Markdown |
|---|---|---|
| 打开 / 拖放 / 最近文档 | ✅ | ✅ |
| 缩放 | 页面缩放 | 字号缩放重排 |
| 页码 / 翻页 | ✅ | 隐藏 |
| 单双页 / 缩略图 | ✅ | 隐藏 |
| 目录 | PDF 书签 | 标题大纲 |
| 批注 / 保存 / 撤销 | ✅ | 隐藏 |
| 阅读位置记忆 | ✅ | ✅（独立键） |
| 文件名搜索 | ✅ | ✅ |
| 转 PDF 引导 | — | ✅ |
| 本地图片 | PDF 内部 | 桌面端同目录/子目录 |
| 外部链接 | 维持现状 | 系统浏览器 |

**其他适配**

- `TitleBar.vue`：目录提示改为通用“目录”；Markdown 隐藏缩略图按钮。
- `SidePanel.vue`：Markdown 只显示文件、搜索、目录、设置；缩略图不渲染。
- `App.vue` 快捷键：Markdown 下 `PageUp/PageDown/Space/Home/End` 改为文档滚动；左右方向键不翻页；批注快捷键不拦截。
- 关闭提醒：Markdown 永远没有“未保存批注”，不触发保存拦截。

### M6. 标题大纲（难度：M）

- 从 Markdown 标题生成树，层级 1–6；无标题时显示明确空状态。
- 点击跳到对应标题，顶部留 16–24px 呼吸空间。
- 滚动时高亮最近经过的标题。
- 标题 `id` 要稳定：中文转写或序号均可，但同一文件重复渲染必须一致。
- 不复用 PDF 的 `OutlineNode` 页码语义；新增 `MdHeadingNode`，避免类型污染。

### M7. 阅读位置记忆（难度：S–M）

新增独立键，避免影响 PDF：

```text
epl:md-reading:<内容指纹>
{
  scrollRatio: number,
  anchorId: string | null,
  anchorOffsetRatio: number,
  scale: number,
  updatedAt: number
}
```

- 恢复优先定位 `anchorId`，失败回退 `scrollRatio`。
- 缩放变化后仍按标题锚点 + 偏移恢复，避免重排导致比例漂移。
- 内容指纹变化视为新文档，不恢复旧位置。
- `epl:last-doc` 继续复用，恢复时按扩展名分流；文件不存在时清记录。

### M8. 转 PDF 引导（难度：S）

`ConvertGuideDialog.vue` 内容：

1. 说明：Markdown 只读，不支持批注；要批注需先转成 PDF。
2. 给出可行方式：Typora / VS Code Markdown PDF 扩展 / Pandoc 等。
3. “复制文件路径”“打开所在文件夹”。
4. “转好后把 PDF 拖回本应用即可批注”。
5. 浏览器版没有真实路径时，说明需在桌面版操作。

不调用任何转换服务，不上传文件。

## 7. 安全设计（重点）

| 风险 | 处理 |
|---|---|
| Markdown 内嵌 HTML/XSS | `html:false` + DOMPurify 白名单；CSP 继续禁止内联脚本 |
| `javascript:` / `data:` 链接 | 协议白名单；点击统一拦截；不在 WebView 内导航 |
| 本地图片路径穿越 | `read_doc_asset` 规范化 + 目录包含校验 + 图片扩展名白名单 |
| 把读取命令变成通用文件读取 | 读文档只放行 pdf/md/markdown；资源读取只放行图片且必须在文档目录内 |
| 远程图片偷偷联网 | 不渲染远程 `src`；CSP 不放宽 `connect-src`/`img-src https:` |
| 大文件拖死 UI | Markdown 文件大小上限；首屏渲染与缩放做性能测量 |
| WebView 内打开外链 | 受控 opener，只允许 http/https/mailto |
| Blob URL 泄漏 | 文档关闭 / 组件卸载时统一回收 |

CSP 预计只需在 `img-src` 增加 `blob:`；若采用受控 Rust opener，则不需要放宽 `connect-src`。

| 优先级 | 工作包 | 内容 | 估计 |

### 10.2 必测项

**入口**

- 对话框、拖放、文件列表、文件夹展开、启动恢复都能打开 PDF 与 Markdown。
- `.md` / `.markdown` / 大写扩展名都识别。

**渲染**

**交互**

- 缩放 75%–250% 文字重排，无整页横向滚动。
- 大纲跳转准确；滚动时当前标题高亮。
- 重开文档恢复缩放与位置。
- Markdown 下没有批注、保存、页码、单双页、缩略图入口。

- `npm test` 全量通过。

- 2–5 MB Markdown 首屏可交互时间需实测并记录。

## 15. 实施记录（2026-11-05）

实现与策划基本一致，下面只记**与策划不同**或**策划没写到**的地方 ——
这些是落地时才暴露的，比"按计划完成"更有参考价值。

| 项 | 决定 / 发现 |
|---|---|
| 依赖 | `markdown-it`（`html:false`）+ `markdown-it-task-lists` + `dompurify`。任务列表**没有手写规则**，但插件生成的 `input[type=checkbox]` 在净化后被换成 `<span class="md-task">` —— 这样"最终产物里没有 input"是可以断言的事实 |
| 删除线 | markdown-it 输出 `<s>` 不是 GFM 文档写的 `<del>`，样式与判据都要认两个 |
| Rust 命令 | **保留** `read_pdf_bytes`（端到端测试拿它当"非 pdf 读不出来"的阴性对照），新增 `read_doc_bytes` 做统一入口；`pick_pdfs` 改名为 `pick_documents` |
| 图片资产 | 新增 `read_doc_asset`，路径解析抽成 `resolve_asset()` 并配 **8 项 cargo 单测** —— 端到端只能证明"读不到"，分不清"被规则拒绝"还是"文件不存在" |
| 外链 | 没有引入 opener 插件；新增 `open_external_url`，Rust 侧校验 `http/https/mailto` + 用 `Command::arg()` 传参（不过 shell） |
| 阅读器 key | 用**自增序号**而不是内容指纹：同一份文件再打开一次时指纹相同，Vue 会复用组件 → `onMounted` 不再执行 → 图片不加载、位置不恢复 |
| 大纲跳转判据 | 必须先轮询到滚动**稳定**再断言，并且要用**相对阅读容器**的坐标（标题栏 + 工具栏占 82px，直接比视口 0 会永远差 82） |
| 位置恢复顺序 | **先改缩放再恢复位置**：字号一变，同一段文字的滚动坐标全变，反过来会先按旧字号定位再被重排推走 |
| 大文件实测 | 2 MB / 4778 个标题：首屏约 **2.2–2.5 s**（无头 Edge，浏览器版）。这个数记在这里作为基线，不是"达标"结论 |
| 页内查找（P2 第 1 项） | 用 **CSS Custom Highlight API** 画高亮，**不往正文插 `<mark>`**：正文是 `v-html` 的、还会因缩放重排，插标记再还原是一条注定会出错的路。`::highlight()` 的样式块**必须非 scoped**，否则 Vue 会拼上属性选择器、整条规则被浏览器丢掉（计数和跳转都对，就是一个字不黄） |
| 代码高亮（P2 第 2 项） | highlight.js `lib/common` **动态 import**：没有代码块的文档不多付一个字节。只认**标注了语言**的块 —— `highlightAuto` 是纯 CPU 消耗还常猜错。token 颜色全部映射主题变量（官方主题是死色值，切主题会瞎）。高亮对象是已转义文本，hljs 自己再转义一遍输出，不会把用户字符串变成元素 |
| 文件类型徽标 | 文件面板 + 搜索面板里，通用文件图标被 **PDF / MD 徽标**替代（前置、等宽对齐，文件夹仍是文件夹图标）；用短标签而不是 "Markdown" 全称 —— 行宽有限，全称会挤掉文件名。只读 `documentKind.ts` 一处判断 |
| 浏览器版本地图片（P2 第 6 项） | **File System Access API**：占位即授权入口，授权的目录句柄存 IndexedDB（下次只需一次点击确认）；`..` 在 API 层面进不来，逃不出授权目录；读不到时占位保留**重新选文件夹**的出路。Firefox / Safari 没有这个 API，退回"仅桌面版"文案。测试用 **OPFS** 根句柄 + 选择器打桩走真代码路径（没有为测试开后门） |
