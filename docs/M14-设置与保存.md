# M14 · 设置面板与保存（另存 / 覆盖）

本轮解决用户提的四件事：

1. **"按下保存之后显示了保存，但我不知道保存到了哪里"** → 设置面板 + 提示里带完整路径 + 「打开文件夹」
2. **保存方式可选：另存 / 直接覆盖原文件**（默认另存）
3. **保存路径可设置**（默认文档库，不是安装目录）
4. **日间 / 夜间模式**
5. 顺带修掉：**Surface 上高亮 / 下划线 / 删除线用不了**（单指一拖页面就跟着动）

代码位置：`src/viewer/settings.ts`、`src/viewer/SettingsPanel.vue`、
`src-tauri/src/lib.rs`、`src/App.vue`（保存逻辑）、`src/viewer/PdfViewer.vue`（触屏选区）。

## 一、保存：两条路，一个提示

| 环境 | 另存 | 覆盖原文件 |
|---|---|---|
| **桌面端（exe）** | 写到设置里的目录（默认 `文档库\edge-pdf-lite\save`） | 写回**原文件路径**，写之前**自动留 `.bak`** |
| **浏览器** | 下载到浏览器的下载目录 | **做不到** —— 选项禁用并写明原因 |

### 默认目录为什么不放在"安装路径下"

用户最初要求"安装路径下面新建一个 save 文件夹"。**这个位置有坑**：
用安装包（NSIS/MSI）装到 `C:\Program Files\...` 之后，那个目录对普通用户是**只读**的，
在里面建子目录会直接失败 —— 表现为"每次保存都报错"。

所以默认改成 **`%USERPROFILE%\Documents\edge-pdf-lite\save`**（文档库），
目录顺手在建的时候一起创建好（`create_dir_all`），用户第一次保存不该遇到"目录不存在"。

> 浏览器版连"目录"这个概念都没有，所以那一栏直接显示"（浏览器的下载目录）"并说明原因。
> **做不到的功能要禁用 + 写清原因**，让它点了没反应是最糟的选择。

### 覆盖为什么要自动 `.bak`

覆盖是不可逆的。没有备份的话"保存完想反悔"就只能重画一遍。

实现上**先备份、后写**，备份失败就整个中止（`?` 直接把错误抛出去，此时原文件还没动）。
所以不会出现"备份没成、原文件已经被盖掉"这种最坏结果。

备份名：`书.pdf` → `书.bak.pdf`（同目录）。已存在就排成 `.bak2`、`.bak3`，
**不覆盖上一份备份**。

### 字节怎么从 JS 传到 Rust

⚠️ **不要用 `Vec<u8>` 参数**。Tauri 的 IPC 是 JSON 序列化的，`Vec<u8>` 会变成
`[12,34,56,...]` 这样的数字数组 —— 20 MB 的 PDF 会膨胀成约 60 MB 文本，
在低配机上光解析就要卡一下。

这里走 **base64 字符串**（1.33 倍），Rust 侧手写解码（省一个依赖）。
JS 侧编码**必须分块**（`String.fromCharCode(...chunk)` 一次展开 20 MB 会爆栈）。

⚠️ **参数名用 camelCase**：Tauri v2 按"前端 camelCase → Rust snake_case"匹配。
写 `make_backup` 会直接报 `missing required key`，保存**静默失败**
（提示条不出现，控制台也不一定有错）。

## 二、主题：一套变量，两套取值

`src/styles/base.css` 定义了全部颜色变量，暗色是默认，`[data-theme='light']` 覆盖一套。

- `system` **不落到 DOM** —— 先解析成 light/dark 再写 `data-theme`，CSS 不用处理"未定"状态
- 滚动条 / 下拉框这些浏览器自带部件靠 `color-scheme` 跟着换
- **PDF 的"纸"永远是白的**（`.page` 写死 `#fff`）：换成变量会让日间模式下的纸变灰，像脏了

替换是脚本做的（132 处），两个必须注意的点：

1. ⚠️ **`--shadow` 是纯颜色**，不是完整的 `box-shadow`。用法是
   `box-shadow: 0 8px 26px var(--shadow)` —— 写成完整值会拼出无效语法。
2. 同一个色值在不同文件里含义不同（`#14161a` 在 `.app` 是应用底、在阅读区是"纸周围"），
   所以替换按**文件 + 用途**分别映射，不能全局一刀切。

**验证用"逐块亮度"而不是看截图**：截图缩小之后 `#f6f7f9` 和 `#eef0f4` 根本分不出来，
漏掉某一块在图上就是"看着差不多"。测试直接读计算样式，
断言日间模式下标题栏 / 功能区 / 侧边栏 / 阅读区的**背景亮度都 > 180**。

> 顺带的一个教训：我看截图判断颜色时得出过相反结论（把浅灰看成深色）。
> 用像素采样才定论：夜间标题栏 `[20,22,26]`、日间 `[238,240,244]`。
> **颜色这种事不要靠眼睛，读数值。**

## 三、触屏上的标记类工具（Surface 老问题）

用户反馈：**"高亮、下划线、删除线在 Surface 上单指一拖，页面跟着动。"**

### 根因

这类工具原本靠**浏览器原生选区**选词。但 viewport 是**可滚动容器**，
浏览器会把这一下先判成 pan 手势 → 自己开始滚动 → 给页面发 `pointercancel`
→ 选区根本建立不起来。

之前这里**故意**没设 `touch-action: none`，理由写在注释里（"标记工具要靠原生选区"）——
这个前提是错的：不设的话在触屏上连选区都建不起来，等于功能不可用。

### 解法（两步缺一不可）

1. **`touch-action: none`**（`.viewport.markup-tool`）——
   这是**手势开始前的声明**，必须工具激活时就切好，等手指落下再改已经来不及。
2. **自己算选区**：原生选区没了，用 `document.caretRangeFromPoint`
   把屏幕坐标换算成文本层里的字符位置，再用 `Range` 拼出来。

细节：

- **只对 `pointerType === 'touch'` 生效**。鼠标继续走原生选区（那条路本来就顺）。
- 起点 / 终点**必须落在 `.text-layer` 里**。命中画布的话选区会横跨整页，
  出来的高亮是**一整块错的东西** —— 靠 `closest('.text-layer')` 挡掉。
- 第二根手指落下 → 放弃划选，转入手势（否则"双指缩放"会把选区撕成两半）。
- 代价：工具激活期间**单指不能翻页**，靠双指平移 / 捏合补（跟绘图工具一致）。

### 测试怎么写才对

⚠️ **测试用的 span 必须挑"当前视口内"的**。文本层里有一百多个 span，
其中大部分滚在屏幕外 —— 对它们的坐标调 `caretRangeFromPoint` 一律返回 `null`
（不是"没命中文字"，是"这个坐标在视口之外"）。
第一版就是踩了这个，症状是 `caret` 恒为 `null`，看着像功能没实现。

判据三条：
1. `touch-action` 是 `none`
2. 单指划过**真的生成了一条 highlight**
3. **划的过程中 `scrollTop` 没变**（证明确实是浏览器没抢走手势）

> 旧测试里那条"标记工具下 `touch-action` 不能是 none"是**基于已经被推翻的前提**写的，
> 这轮把它改成了上面三条。**改测试的前提必须写清为什么**，否则下一个人只会以为是在放宽断言。

- 默认目录在**文档库**且已创建（不是只读的安装目录）
- 提示条里有**完整路径**，且有「打开文件夹」按钮
- 另存的文件 `%PDF-` 头正确、文件名带「已批注」
- **批注数 = 原件 + 1**（用 `@cantoo/pdf-lib` 直查 `/Annots`）
- 覆盖后原文件被改写、`.bak` 存在、**`.bak` 的批注数 = 原件（113）**

⚠️ 判据必须是**精确 +1** 。这个测试样本自带 113 条批注，写成"大于 0"的话
writer 一行都没写也照样绿 —— 那就是假绿。
