## 一、`/AP` 的正确写法（最重要的一条）

### 错误写法（方案 v1 就是这么写的）

```
BBox   = [0, 0, w, h]
Matrix = [1, 0, 0, 1, -rect[0], -rect[1]]      ✗
内容   = 用「页面坐标」画
```

想法是"用 Matrix 把页面坐标平移到注释空间"。**数学上等价于正确写法，但实际不行。**

原因在 pdf.js 的 `getTransformMatrix(rect, bbox, matrix)`：

```js
// pdf.worker.mjs
function getTransformMatrix(rect, bbox, matrix) {
  Util.axialAlignedBoundingBox(bbox, matrix, minMax);   // bbox 先过一遍 matrix
  ...
  return [xRatio, 0, 0, yRatio, rect[0] - minX * xRatio, rect[1] - minY * yRatio];
}
```

**查看器自己会算一次「bbox → Rect」的映射。** 我们再给 Matrix 平移一次 = **双重偏移**。

实测（P1）：

| | |
|---|---|
| bbox 经 matrix 后 | `[-46, -653, 186.7, -618.5]` |
| 算出的 transform | **`[1, 0, 0, 1, 92, 1306]`** |
| 结果 | 高亮被推到页面外，canvas 上一个像素都没有 |

### 正确写法（已采用）

```
BBox   = [0, 0, w, h]          （w,h = /Rect 的宽高）
Matrix = [1, 0, 0, 1, 0, 0]    （单位矩阵，不自己平移）
内容   = 用「注释空间坐标」，即 (页面坐标 - Rect 左下角)
```

符合 ISO 32000-1：外观流画在注释空间里，由查看器负责映射到 `/Rect`。
**不抢查看器的活，两边就都对。**

### 验证（同一次渲染、只切 `annotationMode`）

| 检查项 | DISABLE | ENABLE |
|---|---|---|
| P1 高亮目标色像素 | **0 px** | **12042 px** ✅ |
| P4 墨迹目标色像素 | **0 px** | **2096 px** ✅ |

用「数特定颜色像素」而不是「平均色」：高亮只覆盖采样区一部分，平均色会被白底稀释，
阈值没有灰区可定 —— 自检第一版就是这么失败 `0/2` 的。改成计数后判据是二值的，没有灰区。

## 二、`/Rect` 必须是所有 QuadPoints 的包围盒

多行高亮里各行宽度常常不同。生成器第一版拿「第一行的右边界」当 `/Rect` 右边界：

```
/Rect [46 653 259.336 687.5]         ← 右边界 259.336
/QuadPoints [... 278.692 665.5 46 653 278.692 653]   ← 实际到 278.692
```

**超出的部分会被裁掉** —— canvas 渲染注释时会 `ctx.clip(rect)` 直接用 `/Rect` 裁。
正确做法是取所有四边形的并集：`[46 653 278.692 687.5]`。

## 三、pdf.js **不读** `/NM` —— 「识别自己的批注」要换判据

方案 v1 写的是：

> 读取用 pdf.js 的 `page.getAnnotations()`（返回的 `id` 即 `/NM`）

**实测证伪。** `id` 返回的是**对象引用**（`8R`、`11R`…），pdf.js 6 的 worker 里根本没有读 `/NM` 的代码。

`getAnnotations()` 实际暴露的字段（P1 Highlight）：

| 字段 | 值 | 用途 |
|---|---|---|
| `id` | `"8R"` | **对象引用**，不是 /NM |
| `titleObj.str` | `"edge-pdf-lite"` | = **`/T` 作者名** ← 用它识别自己的批注 |
| `contentsObj.str` | `"P1: highlight WITH /AP..."` | = `/Contents` |
| `overlaidText` | `"Line 2 — HIGHLIGHT TARGET (first).\nLine 3 ..."` | **pdf.js 额外抽出的高亮覆盖文字**，做批注列表很好用 |
| `hasAppearance` | `true` | 有没有 `/AP` ← 自检直接用这个 |
| `opacity` | `0.6` | = `/CA` |
| `quadPoints` | 数组 | Highligh/Underline/StrikeOut 有 |
| `inkLists` | 数组 | Ink 有 |
| `annotationType` | 数字（Highlight 9 / Ink 15 / FreeText 3） | 按类型分支 |

**决定**：识别「哪些批注是我写的」用 `/T` 作者名（固定写 `edge-pdf-lite`）；
`/NM` 仍然写（pdf-lib 侧读回来时用，也是给别的工具的标记），但**不依赖 pdf.js 暴露它**。

## 四、字符串必须显式包 `PDFString.of()`

`PDFContext.obj()` 的重载是这样的：

```ts
obj(literal: string): PDFName;     // ← 传 JS string 会变成 PDFName！
obj(literal: number): PDFNumber;
obj(literal: LiteralObject): PDFDict;
```

于是生成器第一版把 `/T`、`/Contents`、`/NM`、`/M` 全写成了 **Name**：

```
/Contents /P1:#20highlight#20WITH#20#2FAP...     ← #20 是空格的转义，这是 Name 的编码
/T /edge-pdf-lite
```

按规范这些必须是 **text string**：

```
/Contents (P1: highlight WITH /AP, Z-order quadpoints)
/T (edge-pdf-lite)
/NM (epl:p1-c41e6f57-...)
```

**后果**：作者名与批注内容在严格查看器里是错的（注释面板可能显示不出来或显示成路径）。
自家用 pdf-lib 读回来可能"看起来还行"，所以极易漏掉。

自检里加了一条断言守住它：`每条注释的 /Contents 都读得出来（字符串没被写成 PDFName）`。

## 五、`InkList` 用**页面坐标**，不是相对 `/Rect` 的坐标

生成器第一版按"注释空间"写了相对坐标（`x - rect[0], y - rect[1]`）。
实测证据：pdf.js 在没有 `/AP` 时**直接**拿 inkLists 生成内容流，不做任何偏移：

```js
buffer.push(`${inkList[i]} ${inkList[i + 1]} ${i === 0 ? "m" : "l"}`);
```

ISO 32000-1 对该字段的措辞也是 **default user space**（页面坐标）。
有 `/AP` 时这个错误被掩盖（查看器优先用 `/AP`），一旦 `/AP` 缺失就整条错位。已改成页面坐标。

⚠️ 注意与 QuadPoints 的区别：**QuadPoints 是页面坐标，InkList 也是页面坐标** —— 但
两者都**不是**相对 Rect 的坐标。这个混淆很常见。

## 六、标题里的中文全变成 `?`

样本页标题第一版用了中文 + 全角括号，而字体是 `StandardFonts.Helvetica`（WinAnsi 编码）：

> 实际渲染出来：`P4  Ink?????+ /AP`、`P1  Highlight + /AP + QuadPoints Z ?  ????`

**这不是渲染 bug，是编码限制**：WinAnsi 没有中文字形。
已全部改成英文标题。

**对 M5/M6 的影响**（必须提前定）：
- 批注的 **`/Contents`（文字内容）** 用 UTF-16BE 字符串，**中文没问题** —— 与字体无关。
- 但 **FreeText 文本框要在页面上画出中文**，就必须**嵌入中文字体**。
  `@cantoo/pdf-lib` 支持 `embedFont(bytes, { subset: true })`，子集化后只有几 KB，可行。
- 退化方案：FreeText 不生成 `/AP`，只给 `/DA`，让查看器用系统字体渲染（各家表现不一致）。

## 七、顺带确认：pdf.js 的注释渲染走主 canvas

诊断探针（同一页、只切 `annotationMode`）：

| 指标 | DISABLE | ENABLE |
|---|---|---|
| 算子列表长度 | 71 | **81** |
| `separateAnnots` | `null` | `{"form":false,"canvas":false}` |

`separateAnnots.canvas = false` → 注释**不需要**独立 canvas / DOM 层，直接画在主 canvas 上。
我们的阅读器只要用 `annotationMode: ENABLE` 渲染，PDF 里已有的批注就会显示出来
（这正是之前"笔记不见了"的修法）。

`cacheKey` 也确实包含 `annotationMode`，所以**不存在"先 DISABLE 渲染过、后来切 ENABLE 就不生效"**的缓存污染。

## 八、待人工核对（我跑不了的部分）

`edge-pdf-lite` 只能证明 pdf.js 能画。**Edge / Acrobat 是另外的实现，必须人工过一遍。**

在 `/annot-check.html` 下半部分有逐页清单。**最要紧的三条对照：**

| # | 看什么 | 含义 |
|---|---|---|
| 1 | **P2 是不是空白**（无 `/AP`） | 空白 → `/AP` 是**必须**生成的，写回方案强制带上它；能画出 → `/AP` 是加分项 |
| 2 | **P3 与 P2 相比有没有错位/翻转**（逆时针序 vs Z 序） | 有差异 → QuadPoints 顺序真的有影响，一律用 Z 序 |
| 3 | **P7 是不是和 P1 一模一样**（有 `/AP` + 逆时针序） | 一样 → 有 `/AP` 时顺序无所谓，`/AP` 是最终兜底 |

## 九、对后续阶段的影响

| 阶段 | 原计划 | 修正后 |
|---|---|---|
| M5 批注显示 | 自绘 canvas overlay | **pdf.js 用 `AnnotationMode.ENABLE` 渲染已有批注**（含用户原有的笔记）；overlay 只画"正在编辑、尚未保存"的 |
| M5 坐标系 | 走 `baseVp` | 不变，但要注意 **QuadPoints / InkList 都是页面坐标**，转视口要过 `viewport.convertToViewportPoint` |
| M6 写回 `/AP` | `Matrix` 平移 + 页面坐标 | **单位 Matrix + BBox `[0,0,w,h]` + 注释空间坐标** |
| M6 写回字符串 | 直接传字符串 | **一律 `PDFString.of()`** |
| M6 识别自己的批注 | `getAnnotations().id === /NM` | **用 `/T === 'edge-pdf-lite'`**；`/NM` 仅作写回侧的标记 |
| M6 `/Rect` | 手填 | **取所有 QuadPoints 的包围盒** |
| M6 中文批注文本 | 未考虑 | `/Contents` 走 UTF-16BE（天然支持）；**FreeText 要画中文必须子集化嵌入字体** |
