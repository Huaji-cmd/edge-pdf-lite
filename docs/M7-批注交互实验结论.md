## 一、做了什么

| 功能 | 交互 | 关键实现 |
|---|---|---|
| **选色** | 工具激活或选中批注时，工具栏出现 10 色色板 | 工具色存 `localStorage`（`epl:tool-colors`）；有选中项时点色板 = 改**这一条**（走历史，可撤销），否则改工具的默认色 |
| **拖动** | `选择`模式下按住批注本体拖 | `translateAnnot` → 存的是页面坐标，与缩放无关 |
| **改大小** | 8 个手柄（NW/N/NE/E/SE/S/SW/W） | `resizeRect(r, handle, dx, dy)`；最小尺寸夹到 6pt |
| **指针模式** | 工具栏三态：`选择` / `滚动` / `拖动` | 见下 |
| **重做** | `重做`按钮 + `Ctrl+Shift+Z` / `Ctrl+Y` | store 两个栈，`add`/`remove`/`edit` 三种操作都天然可逆 |

### 三种指针模式到底差在哪

不是"三种都差不多"——每一条都对应一个真实误操作：

| 模式 | 左键在页面上做什么 | 为什么需要它 |
|---|---|---|
| **选择** | 点批注 → 选中并准备拖动；点空地 → 交给浏览器选文字 | 编辑批注的默认态 |
| **滚动** | 什么都不做（只阅读 + 选文字） | 翻页时点一下就把批注拖走了 —— 而批注是**内容**，拖坏了很难发现 |
| **拖动** | 按住左键抓手平移 | 放大到 300% 后唯一舒服的移动方式（滚轮只能上下） |

**三态互斥由 `App.vue` 保证**，不留给用户猜：

- 选任何一个批注工具 → 自动回到 `选择`（否则"工具选中了但 pointerdown 被模式吃掉"，
  症状是"点了没反应"，很难联想到是模式问题）
- 切到 `拖动` → 自动清空工具（抓手和工具都想要左键，并存就是"到底画还是拖"的歧义）
- 工具优先级：**工具 > 拖动 > 选择**（选中框上的手柄/框体例外，永远优先，否则手柄点不中）

## 二、踩到的真问题（都是实测才暴露的）

### 1. 文本框建完不退出工具 → 拖不动 🔴

**现象**：拖动画好的文本框，纹丝不动，反而又弹出一个输入框。

**原因**：`freetext` 工具在创建完成后仍然激活，`pointerdown` 走的是"新建"分支。

**修法**：建完置 `tool='none'` 并通知宿主（`onToolAutoExit`）。
配套要求 —— `setTool()` 必须**同值早退**，否则"通知宿主 → 宿主回设 none → watcher 调
`setTool('none')` → 顺手清掉刚建好那条的选中态"，白忙一场。

⚠️ **只有文本框自动退出**。手写/方框/高亮**不退出**：在扫描版教材上连续写十几笔是常态，
每笔都要重新点一次工具会让人崩溃。

### 2. `markup-tool` 光标类从来没被绑上（死代码）

`.viewport.tool-active.markup-tool { cursor: text }` 这条 CSS 一直在，但模板里只绑了
`tool-active` —— 于是用高亮工具时鼠标是**十字准星**而不是文本光标，"去选文字"这个暗示完全没给到。
顺手补上。

### 3. `Ctrl+Shift+Z` 的分支顺序

`e.key` 在按下 Shift 时是**大写 `Z`**。`ctrl && (e.key === 'z' || e.key === 'Z')` 会先命中撤销，
重做分支永远走不到。**判断顺序必须把 Shift 版排在前面。**

### 4. `add`/`remove` 不带 index 会悄悄改变叠放次序

批注是"后加的在上层"。撤销再重做如果一律追加到末尾，`谁盖住谁`就变了。
`UndoOp` 里 `add`/`remove` 都带 `index`。

## 三、拖动/改大小的几何：为什么必须统一映射

高亮类批注的几何**不是一个 rect** —— 它还有 `quads`（每行文字一个四边形）；
手写还有 `strokes`。只改 `rect` 会同时错两处：

1. 界面上"框动了、黄底没动"
2. 写回 PDF 后 `/Rect` 与 `/QuadPoints` 不一致 —— 而 `/Rect` 是"所有 QuadPoints 的包围盒"，
   查看器会按它裁 `/AP`，**高亮被截断**

所以统一走 `src/annot/geometry.ts` 的 `mapAnnotToRect(a, from, to)`：
把 `from` 框线性映射到 `to` 框，**批注里所有坐标一起走同一个映射**，
markup 的 `rect` 由 `quads` 重算、ink 的 `rect` 由 `strokes` 重算。

**y 轴方向是这里唯一的坑**：屏幕上的「上」(n) 对应 rect 的 **y1**（大值），不是 y0。
写反了的表现是"往上拖框往下长"，而且**只在拖动过程中可见**，静态看代码看不出来。

**高亮类只允许平移，不给手柄** —— 拉伸高亮会脱离原文，没有意义。

## 四、撤销/重做：一次拖动 = 一条历史

拖动过程中 `pointermove` 一秒能来 100+ 次。如果每次都记一条历史，撤销栈会被瞬间淹掉，
用户按一次 Ctrl+Z 只退回到上一帧 —— 完全不符合"撤销刚才那个动作"的直觉。

做法：过程中直接 `store.replace()`（不入栈），**松手时** `store.commitEdit(before, after)`
补一条 `edit` 记录（`before` 是按下前的完整快照）。

⚠️ `before` 必须存**快照**：`replace` 是把数组元素换成新对象，**不会改动旧对象**，
所以那份 `original` 到松手时仍然是"拖动前"的样子。

## 五、验证方式

`scripts/test-interact.mjs`（零依赖 CDP，发**真实鼠标事件**），54 项断言，覆盖：
色板生效（数据 + 画布像素双通道）→ 文本框创建/拖动/改大小 → 撤销/重做各两次 →
选中项改色 → 三种指针模式 → Delete 删除 + 撤销 → **拖动高亮 + 内容不越界不变量** → 控制台。

最后那组「不变量」值得单独说：拖动/改大小最容易犯的错是**只改了 `rect`、没改 `quads`/`strokes`**。
界面上只是"框动了、内容没动"（很难一眼看出），但写回 PDF 后查看器按 `/Rect` 裁 `/AP`，
高亮会被**截断**。所以断言直接查 `contentInsideRect`（markup 的 rect 必须**正好**是 quads 的包围盒）。
截图缩略图上"看着像有手柄"分不清，所以"手柄数"也一样用 DOM 数出来而不是看图。

**为什么单开一个脚本**：`test-viewer` 的断言建立在"页面上没有批注"的前提上
（比如"高亮是黄色"），而这一套偏偏要把高亮改成绿色 —— 混在一起会互相干扰。

**判据为什么是双通道**：
- 只查数据 → 抓不到"数据对了但没画出来"
- 只查像素 → 抓不到"框没动"（画的东西本来就没变）

截图存 `interact-shots/`，**已人工核对**：绿色高亮、蓝色手写、带 8 个手柄的文本框、
拖动模式平移后的版面。

## 六、已知限制 / 下一步

- **打开 PDF 时文件里已有的注释不进 store** → 点不中、拖不了（符合"只擦自己画的"，但要在 UI 说明）
- **删除是 Delete 键或「删除所选」按钮**；擦除工具仍然按"点哪儿擦哪儿"
- 改大小只改框，**不缩放字号**（与 PDF 的 FreeText 语义一致：`/DA` 里是固定字号）
- 触屏上 10px 的手柄偏小（本项目目标是桌面，暂不处理）
- 手势缩放**结束后**才重算选中框位置（`previewScale` 期间靠 CSS transform 一起缩放，
  所以视觉上不会脱节）
