### 1.3 提交

单个初始提交（`feat: 轻量 PDF 阅读 + 批注编辑器（M0–M9）`），
body 里列了里程碑和四条工程约束 —— 代码是一次性长出来的，硬拆成多个提交是假历史。

🔴 **推公开仓库前必须检查 `user.email`**：邮箱会被写进**每一个提交**，
如果它含手机号之类的个人信息，一推送就等于公开了。

⚠️ 而且**光改当前配置没用** —— 历史里的旧提交照样带着。
要改就得重写历史：

```bash
git config user.email "<你的 GitHub noreply 邮箱>"
git filter-branch -f --env-filter 'export GIT_AUTHOR_EMAIL="..."; export GIT_COMMITTER_EMAIL="..."' -- --all
git for-each-ref --format="%(refname)" refs/original/ | xargs -n1 git update-ref -d   # ← 别漏这步
git reflog expire --expire=now --all && git gc --prune=now
```

⚠️ **`refs/original/` 那步最容易漏**：`filter-branch` 会把重写前的提交备份在这个引用下，
不删掉的话它们**依然可达**（`git log --all` 还能看到），等于没改。

## 二、退出提醒（替代"自动暂存"）

用户明确要求：**不替用户暂存**，但要像 Word 那样在退出时提醒。

### 2.1 三个拦截点

| 行为 | 拦截方式 |
|---|---|
| 刷新 / 关标签 / 关窗口 / 浏览器后退 | `beforeunload` |
| **应用内换文档**（点「打开 PDF」或拖入新文件） | `window.confirm` |
| 切到后台 / 移动端被杀 | `pagehide`（只落盘阅读位置，不拦截） |

⚠️ 第二条**必须单独做**：换文档走的是 `openBytes`，页面压根没卸载，
`beforeunload` 根本不会触发 —— 而它恰好会**清空整个批注 store**。
只做 `beforeunload` 的话，这条路径是静默丢数据的。

### 2.2 「有没有未保存」的判据

```ts
annotStore.count() > 0 && annotStore.dirtyPages().size > 0
```

两个条件都要：

- 只有 `dirty` 不行 —— **画了一条又撤销掉**的页也是脏的，但一条批注都没有，
  拦下来纯属骚扰；
- 只有 `count` 不行 —— 导出过之后批注还在内存里显示，但已经落盘了。

导出成功后调 `markSaved()` 清脏标记，之后再退出就不拦。

### 2.3 ⚠️ 两个必须知道的浏览器限制

1. **现代浏览器不显示我们给的文字**。`preventDefault()` / `returnValue` 只是一个开关，
   浏览器永远显示它自己那句（"你确定要离开此页面吗？"）。
   → 所以**真正的信息要靠页面内的可见标记**提前传达（工具栏那个琥珀色「● 未保存」），
   等拦截弹窗出来已经晚了。
2. **要求页面发生过用户交互**才真的弹（防滥用）。我们的场景天然满足：
   有未保存批注就一定点过或画过。

## 三、区域高亮（B1）

### 3.1 为什么需要

《现代操作系统教程》是**整页扫描图**，没有文本层。而 TextMarkup 类批注
（高亮/下划线/删除线）**必须依附文字** —— 在这本书上一条都画不出来。
这类书的标注需求其实只是"把这一段盖住"，压根不需要知道文字在哪。

### 3.2 设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 数据模型 | 新增 `kind: 'area'`（不是复用 highlight） | 区域高亮**可以改大小**，而文本高亮只能平移（拉伸会脱离原文） |
| 写回的子类型 | **标准 `/Highlight`**，QuadPoints = 矩形四角 | 不发明新类型 → 任何查看器（PDFium/Acrobat/pdf.js）都能画 |
| 渲染层 | `under` 层（`mix-blend-mode: multiply` + alpha=1） | 跟文本高亮同一条路径：**染背景**，不是盖色板 |
| 色板 | 用 `HIGHLIGHT_SWATCHES`（挡掉黑/白） | 同一个理由：黑会把内容乘黑、白等于没画 |

### 3.3 改动清单

```
types.ts    AnnotKind/ToolKind/COLOR_TOOLS/PALETTE 加 area
            AreaAnnot 接口；isResizable 加 area（可拉伸）
            swatchesFor / sanitizeToolColor 抽 blendsIntoBackground()
draw.ts     blendGroupOf: area → under；globalAlpha=1；填充矩形
editor.ts   Session.kind 加 'area'；pointerDownTool / paintDraft / pointerUp 分支
geometry.ts mapAnnotToRect 走 rect 分支（本来就对）
writer.ts   新增 multiplyGs()（与文本高亮共用）；area → /Highlight + Z 序 QuadPoints
toolbar     加「区域高亮」按钮
```

## 四、B2 的评估结论：**不做字体嵌入**

原建议是"子集化嵌入 CJK 字体（引入 fontkit）"。评估后**不采纳**：

| 障碍 | 说明 |
|---|---|
| **拿不到字体文件** | 浏览器**读不了系统字体**（没有文件系统访问）。要嵌入就必须把字体打包进应用 |
| **体积** | 即使子集化只嵌用到的字，**源字体文件必须完整** —— 一个 CJK 字体 TTF 是 8–19 MB，跟 lite 定位（主包 120 KB）冲突 |
| 依赖 | `@cantoo/fontkit` 未安装，且它会让 pdf-lib 的动态 chunk 再长一截 |

### 4.1 改成"诚实降级"

原来中文 FreeText 的 `/AP` 只画一个**白底灰框**，注释还写着"交给查看器用系统字体渲染" ——
**这个想法是错的**：只要给了 `/AP`，查看器就用 `/AP`，不会自己再补文字。
实际结果是用户在 Edge / Acrobat 里看到一个**莫名其妙的白色空框**。

现在改成画**占位横线**（5 条灰度递减长度的横条）：一眼能看出"这里有个文本批注"，
文字本身在 `/Contents` 里一个字节都没丢（应用内和注释面板都能看全）。

⚠️ 一个测量坑：第一次在 Edge 里核对时"没看到框"，差点当成 bug。
实际是**页面在 150% 缩放下高 1263px，比 1050px 的窗口还高，下半部被裁掉了**。
`edge-pdf-shot.mjs` 因此加了 `EPL_ZOOM` 环境变量。

### 4.2 如果将来真要中文可见

唯一可行路线是**让用户在导出时选一个字体文件**（而不是打包字体）：
`input[type=file]` 选 `msyh.ttc` / `simsun.ttc` → `embedFont(bytes, { subset: true })`。
代价是要装 fontkit、处理 TTC 解析、还要谈字体许可。**要做再单独开一轮。**

## 五、B3：UI 说明（不做载入）

文件里已有的注释不进 store（符合"只改自己画的"），但对用户来说那批批注是
"看得见却点不动" —— 不说明就会被当成工具坏了。

按建议只做 UI 说明（在欢迎页加一行琥珀色警示），**不做**"用 `/T` 识别自家批注并载入 store"
（那会让"擦除"的语义变复杂，破坏现在这条干净的设计）。

## 六、验证

### 6.1 区域高亮的关键对照

⚠️ **必须在真正没有文本层的样本上测**。

第一次尝试是在文字版 PDF 上找"空白处"做对照，**失败了**：拖动经过空白区时
浏览器照样会把附近的文字选进选区 —— 对照根本不成立。

于是新写了 `scripts/make-scan-sample.mjs`，生成 `scan-like.pdf`：
整页**只用矢量图形**（深灰横条模拟文字行），**一个字都不写**，确保没有文本层。

| 断言 | 结果 |
|---|---|
| 样本确实没有文本层（`span` 数） | **0** |
| 扫描件上文字高亮**画不出来** | count = 0 ✅ |
| 扫描件上区域高亮**能画出来** | ✅ |
| 画在 under 层且 alpha 满格 | 44600 px ✅ |
| 给 8 个改大小手柄、能拉大 | 宽 297 → 351 pt ✅ |
| 写回后是标准 `/Highlight` | `QuadPoints=330,700,550,700,330,600,550,600` ✅ |
| **Edge(PDFium) 里文字透出** | 黄底黑字清晰可读 ✅ |

顺带在 [12] 小节验证了换文档的确认框（`Page.javascriptDialogOpening` + accept）。
⚠️ CDP 下对话框**不处理会把页面卡死**，而且默认是 dismiss（等于用户点"取消"），
看起来像"换文档功能坏了"。
